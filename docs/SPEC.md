# LAN-Drop Technical Specification

## 1. Загальний огляд
LAN-Drop — це високопродуктивна кросплатформна система передачі файлів для локальних мереж (LAN/Wi-Fi) з гібридною підтримкою зовнішніх хмарних релеїв (Cloud Relay) та мобільної інтеграції.

## 2. Функціональні вимоги

- **Мережеве виявлення вузлів (Discovery)**:
  - UDP мультикаст маяки на порту 8848 (`LANDROP_BEACON|Name|UUID|Port`).
  - Фільтрація локальних пристроїв та хмарних ретрансляторів через шаблонну функцію `filterPeers<T>()`.
  - Можливість прямого підключення за IP-адресою та портом із валідацією введених даних.

- **Швидке спарювання через NFC (NFC Quick-Pair)**:
  - Стандартний формат NDEF корисного навантаження: `LANDROP:NFC:v1;id=...;name=...;ip=...;port=...;pin=...;key=...`.
  - Автоматичне генерування та розбір конфігурації сесії з перевіркою коректності полів.

- **Apple AirDrop сумісність**:
  - Анонсування служби `_airdrop._tcp.local.` через Bonjour/mDNS.
  - Обробка запитів `/Discover` та `/Ask` з узгодженням блокової передачі.

- **Блокова передача та цілісність (Chunked Transfer)**:
  - Розбиття файлів на блоки (чанкі) фіксованого розміру (за замовчуванням 64 KB, ліміт чанку 4 MB).
  - Контроль цілісності блоків та всього файлу за допомогою хешування SHA-256 (`FileChunkHasher`).
  - Запис у тимчасові файли `*.part`, атомарне перейменування після перевірки повного хешу та очищення при розриві сокету або невідповідності хешу.
  - Моделювання станів передачі (`Idle`, `Connecting`, `Transferring`, `Paused`, `Completed`, `Failed`, `Cancelled`).

- **Спільне сховище (Shared Folder Storage)**:
  - Сканування локальної директорії, індексація метаданих файлів, кількості блоків та контрольних сум.
  - Захист від Path Traversal (`isSafeFileName`) та блокування виходу за межі каталогу через символьні посилання (`std::filesystem::relative`).
  - Обмеження максимального розміру файлів (`m_maxFileSizeLimit`, за замовчуванням 10 ГБ) для захисту від переповнення диска.
  - Захист доступу через PIN-код (4–32 символи) з обов'язковою верифікацією наявного PIN перед зміною чи видаленням.

- **Збереження конфігурації (Settings Persistence)**:
  - Збереження у стандартних системних шляхах через Qt `QStandardPaths::AppConfigLocation` або переносимий fallback `~/.config/landrop/settings.json`.
  - Зворотна сумісність із застарілими та строковими полями (`port`, `speed_limit_kbps`, `auto_accept`, `airdrop_enabled`).
  - Стійкість до некоректного чи пошкодженого JSON зі збереженням поточних налаштувань.
  - Обмеження швидкості передачі (Speed Limit), що синхронізується з бізнес-логікою `TransferPresenter`.

- **Графічний інтерфейс (GUI)**:
  - **Qt 6 Widgets (`lan_drop gui`)**:
    - Сучасний модульний інтерфейс із 4 основними вкладками: Радар виявлення (`QtDiscoveryWidget`), Передачі (`QtTransferWidget`), Спільне сховище (`QtStorageWidget`), Налаштування (`QtSettingsWidget`).
    - Підтримка темного та світлого оформлення через зовнішні QSS-стилі.
    - Двосторонній обмін сигналами: вибір знайденого вузла для відправки файлу, оновлення налаштувань, експорт журналів.
    - Таймер синхронізації (300 мс) для живого відображення прогресу передачі без блокування UI.
  - **GTK+ 3.0 (`lan_drop_gtk gui` / `mobile-gui`)**:
    - Десктопний режим: стиль macOS HIG (traffic lights, сегментовані кнопки, картки вузлів).
    - Мобільний режим: вертикальна компоновка 390x812, нижня навігаційна панель.

## 3. Нефункціональні вимоги
- **Мова програмування**: C++20 (ISO/IEC 14882:2020).
- **Графічна підсистема**: Qt 6 (основний інтерфейс), GTK+ 3.0 (альтернативний інтерфейс).
- **Мережеві протоколи**: POSIX TCP сокети для передачі даних, UDP для мультикаст маяків, OpenSSL 3 для TLS/HTTPS.
- **Безпека TLS**:
  - Обов'язкова перевірка ланцюжка сертифікатів (CA validation) за замовчуванням.
  - Обов'язкова валідація імені хоста (`X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS`).
  - Підтримка відбитку сертифіката (fingerprint pinning) для самопідписаних сертифікатів.
  - Заборона витоку чутливих даних (токенів, паролів, приватних ключів) у системні логи.
- **Безпека пам'яті**: RAII, `std::shared_ptr`/`std::unique_ptr`, відсутність витоків пам'яті.
- **Продуктивність**: Стрімінг блоками до 64 KB / 4 MB для передачі файлів будь-якого розміру (10+ ГБ) без надмірного споживання RAM.

## 4. Статус реалізації функцій

| Функціональний модуль | Статус реалізації | Деталі та примітки |
|---|---|---|
| **Єдиний рушій передачі (`TransferEngine`)** | **Реалізовано та перевірено** | Спільний для CLI та Qt GUI, потоковий сокетний TCP-протокол, чанки 64 КБ–4 МБ, атомарне перейменування `.part`, SHA-256. |
| **Qt 6 Десктопний GUI** | **Реалізовано та перевірено** | 4 вкладки, темна/світла теми, вибір піра або direct IP:port, захист PIN, скасування передачі, 15/15 GUI тестів пройдено. |
| **GTK3 Десктопний & Мобільний GUI** | **Реалізовано та перевірено** | Збережено повну функціональність macOS HIG та адаптивного мобільного вікна 390x812. |
| **MVP Архітектура Presenter/View** | **Реалізовано та перевірено** | Повна ізоляція бізнес-логіки від UI; спільні Presenter для Qt та GTK. |
| **Мережева передача TCP (CLI `send`/`receive`)** | **Реалізовано та перевірено** | Переведено на `TransferEngine`; перевірено передачу 1 МБ та 10 МБ між процесами з побітовим збігом SHA-256. |
| **Безпека TLS/HTTPS (OpenSSL 3)** | **Реалізовано та перевірено** | За замовчуванням перевірка CA та імені хоста; відхилення truncated відповідей; опціональний `allowInsecureTls`. |
| **Криптостійкий PIN (PBKDF2-HMAC-SHA256)** | **Реалізовано та перевірено** | 16-байтна сіль, 100,000 ітерацій, `CRYPTO_memcmp`, прогресивна затримка проти перебору, авто-міграція застарілих хешів. |
| **Безпека сховища (Shared Storage)** | **Реалізовано та перевірено** | Блокування виходу за межі каталогу (Path Traversal), валідація цільових шляхів симлінків, ліміт 10 ГБ. |
| **Стійке збереження налаштувань** | **Реалізовано та перевірено** | Збереження в `AppConfigLocation`/XDG, парсинг застарілих ключів, збереження цілісності при пошкодженому JSON, синхронізація Speed Limit. |
| **Шаблонний буфер чанків `ChunkBuffer<T>`** | **Реалізовано та перевірено** | Потокобезпечний буфер FIFO, покритий тестами. |
| **Хешування SHA-256 (`FileChunkHasher`)** | **Реалізовано та перевірено** | Повна перевірка цілісності файлів і блоків, покритий тестами. |
| **C-ABI / FFI Bridge (`LandropMobileBridge`)** | **Реалізовано та перевірено** | Експорт функцій для зв'язку з Flutter/Kotlin/Swift, перевірено виклики. |
| **Обмеження швидкості передачі (Speed Limit)** | **Реалізовано та перевірено** | Логіка throttling реалізована в сокетному циклі `TransferEngine` та `TransferPresenter`, перевірена тестами. |
| **Справжнє переривання/відновлення (Pause/Resume)** | **Уточнено специфікацію** | У прямому сокетному стрімінгу без протокольного byte-offset resume кнопки Pause/Resume чесно вимкнені з підказками; працює повноцінне скасування (Cancel) з видаленням `.part`. |
| **AirDrop сумісність (`AirDropProtocolBridge`)** | **Частково реалізовано** | Формування протокольних структур Bonjour/HTTP `/Discover` та `/Ask` у пам'яті; без зв'язку з демоном Avahi та апаратним AWDL/BLE. |
| **NFC Fast Pairing (`NfcPairingSession`)** | **Частково реалізовано** | Формування та парсинг текстового NDEF payload `LANDROP:NFC:v1`; без взаємодії з апаратним NFC контролером Linux/Android. |
| **Хмарне реле / Квоти (`CloudPeer`, `HttpClient`)** | **Частково реалізовано** | HTTP клієнт виконує реальні TLS запити та валідацію REST JSON; робота зі справжнім сервером реле залежить від доступності віддаленого бекенду. |
| **Автоматичне мультикаст-виявлення в LAN** | **Не вдалося перевірити в цьому середовищі** | Логіка `MulticastBeacon` реалізована та протестована локально; повноцінне виявлення потребує двох фізичних/віртуальних пристроїв у спільній L2/L3 мережі без блокування IGMP/мультикасту. |

## 5. Вимоги до тестового середовища
Для повної валідації мережевих функцій у фізичній мережі необхідні:
1. Два окремі хости (або віртуальні машини в режимі bridge) у спільній IP підмережі.
2. Маршрутизація IGMP та відсутність фільтрації UDP мультикасту на порту 8848.
3. Дозвіл вхідного TCP трафіку на робочий порт LAN-Drop у мережевому екрані.
