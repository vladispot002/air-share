# Engineering Rules & Guidelines

Усі зміни у кодовій базі LAN-Drop повинні неухильно відповідати таким правилам:

## 1. Zero-Comments Policy
- У доданому або модифікованому коді **заборонено використовувати коментарі** (`//` або `/* */`).
- Код має бути самодокументованим завдяки точним найменуванням функцій, типів та змінних.
- Повідомлення комітів мають бути лаконічними без зайвого описового тексту.

## 2. Стандарти кодування C++20
- Компіляція виключно з прапорцями `-std=c++20 -Wall -Wextra -Wpedantic`.
- 0 попереджень компилятора при збірці.
- Використання RAII для керування ресурсами сокетів, файлів та пам'яті.
- Використання розумних вказівників (`std::unique_ptr`, `std::shared_ptr`).
- Запобігання копіюванню важких об'єктів (передача по константному посиланню `const &` або `std::move`).

## 3. Безпека потоків та пам'яті
- Всі виклики оновлення віджетів GTK3 повинні відбуватися виключно в головному потоці або через `g_idle_add`.
- Мережеві та файлові операції введення-виведення мають бути захищені перевіркою кодів помилок або обгортками винятків.

## 4. Вимоги до тестування
- Жоден коміт не приймається без проходження всіх модульних тестів (`make test`).
- Загальна кількість пройдених тверджень (assertions) не повинна зменшуватися при додаванні нової функціональності.
